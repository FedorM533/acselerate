# Carpo Pond — геймдизайн и техническая спецификация (v1)

Carpo — приложение, которое на телефоне и компьютере блокирует отвлекающие приложения и сайты на время фокус-сессии. **Carpo Pond** — созерцательный слой поверх фокус-сессий: личный японский пруд с карпом, который медленно наполняется жизнью благодаря реальному времени фокуса.

Это не отдельная игра. В неё не нужно заходить ради заданий, рыбу не нужно кормить, пруд никогда не портится.

---

## 1. Принципы (нарушать нельзя)

1. **Время превращается в мир.** Прогресс виден через изменения пруда, а не через цифры. На главном экране нет XP, очков, уровней, процентов.
2. **Без наказаний.** Пропустил неделю — пруд такой же. Ничего не вянет, карп не грустит, ничего не отбирается. Открытое однажды остаётся навсегда, даже если поменяются числа в конфиге.
3. **Прерванная сессия не обнуляется.** Фактически отработанные минуты засчитываются всегда. Указанная причина даёт небольшой бонус.
4. **Регулярность ускоряет, но не требуется.** Нет серий («стриков»). Некоторые открытия требуют N *разных* дней фокуса — но эти дни никогда не сгорают.
5. **Не отвлекать от работы.** Во время сессии пруд — спокойный фон, без событий. Все появления — только после завершения сессии. Никаких push-уведомлений про пруд.
6. **Игра отделена от блокировки.** Таймер считает время, блокировщик ограничивает, пруд только отображает. Сбой блокировщика не может отнять награду.

## 2. Как выглядит

- Вид на пруд **сверху**, во весь экран. Холст 1000×1600 (портрет), на других экранах — масштабирование «cover».
- В центре плавают карпы, по краям — камни, растения, кувшинки. Освещение зависит от времени суток (день / вечер / ночь).
- Внизу — карточка: выбор длительности (25 / 45 / 60 мин) и одна главная кнопка **«Начать фокус»**.
- Эталон: `preview/pond-preview.html` (открывается в браузере) и скриншоты `preview/screens/`.

## 3. Единица прогресса — «капля»

Пользователь капли не видит (только в экране статистики можно показать часы фокуса). Все числа — в `config/progression.json`.

| Правило | Значение v1 |
|---|---|
| 1 капля | 1 полная минута фокуса |
| Минимум, чтобы сессия засчиталась | 120 секунд (иначе статус `too_short`, 0 капель) |
| Засчитываемое время сессии | `min(факт, план, 180 мин)` |
| Лимит базовых капель в сутки | 720 (защита от сбоев часов) |
| Бонус за завершение | +20% от базы, максимум +10 |
| Бонус за причину прерывания | +10% от базы, максимум +3, только если база ≥ 5, не более 3 раз в сутки |
| Прерывание без причины | только база |
| «День фокуса» | календарный день (локальный), где набрано ≥ 10 базовых капель |

**Важно:** проценты считать только в целых числах: `ceil(base * p / 100) = (base * p + 99) / 100`. С плавающей точкой `0.2 * 45 = 9.000000000000002 → ceil = 10` — ошибка (есть тест-вектор `float_trap_45`).

Пример: план 45 мин, через 20 мин срочно ушёл и выбрал «Срочное дело» → 20 + 2 = 22 капли. Без причины → 20. Завершил все 45 → 45 + 9 = 54.

Все причины дают одинаковый бонус — честный ответ «Сложно сосредоточиться» не должен быть невыгоднее, чем «Задача готова раньше».

## 4. Статусы сессии

| Статус | Когда | Капли |
|---|---|---|
| `completed` | таймер дошёл до конца | база + бонус завершения |
| `interrupted_with_reason` | нажал «Завершить» и выбрал причину | база + бонус за причину (с ограничениями) |
| `interrupted_no_reason` | нажал «Просто завершить» / закрыл вопрос / приложение убито во время сессии | база |
| `too_short` | меньше 120 с фактического фокуса | 0 |

Если приложение было убито или устройство перезагрузилось во время сессии — при следующем запуске сессия закрывается как `interrupted_no_reason` с фактически отработанным временем (по сохранённому старту и последнему «пульсу» таймера, не больше плана).

## 5. Открытия (что растёт в пруду)

Открытие доступно, когда `капли ≥ requires.drops` И `дни фокуса ≥ requires.focusDays`. Полный список с координатами — `config/progression.json → unlocks`.

| # | Открытие | Капли | Дни | MVP |
|---|---|---|---|---|
| 0 | Старт: карп Кохаку, 3 камня, вода | 0 | — | ✓ |
| 1 | Первая кувшинка | 15 | — | ✓ |
| 2 | Тростник | 45 | — | ✓ |
| 3 | Новые листья + бутон лотоса | 90 | — | ✓ |
| 4 | Мох на камнях (замена ассетов) | 150 | — | ✓ |
| 5 | Лотос распускается (замена бутона) | 240 | — | ✓ |
| 6 | Коряга | 360 | — | ✓ |
| 7 | Золотой карп (Огон) | 500 | 5 | ✓ |
| 8 | Папоротник | 700 | — | ✓ |
| 9 | Каменный фонарь (+ свечение вечером/ночью) | 900 | 8 | ✓ |
| 10 | Карп Танчо | 1200 | 12 | ✓ |
| 11 | Белый лотос + лист с завёрнутым краем | 1500 | — | |
| 12 | Светлячки (вечер/ночь) | 1800 | — | |
| 13 | Ветка сакуры + падающие лепестки | 2200 | 20 | |
| 14 | Карп Санке | 3000 | 30 | |
| 15 | Карп Асаги | 4200 | 45 | |
| 16 | Платиновый карп | 6000 | 60 | |

Темп: 1 сессия 25 мин в день ≈ 30 капель/день → все MVP-открытия примерно за 40 дней. 2 сессии по 45 мин ≈ 108 капель/день.

**Стадии** (только для внутренней логики и экрана статистики): «Первое дыхание» 0+, «Жизнь в воде» 120+, «Свой уголок» 900+.

**Типы открытий:**
- `placements` — новые объекты (ключ `key` уникален).
- `replace` — заменить ассет у уже существующего ключа (камень → камень с мхом, бутон → цветок) с плавным перетеканием.
- `koi` — новый карп.
- `ambient` — фоновые частицы (светлячки, лепестки), можно с ограничением по времени суток.
- `timeOfDay` у объекта — показывать только в эти фазы.

## 6. Экраны и сценарии

### 6.1 Главный (пруд, ожидание)
Заголовок «Твой пруд», подзаголовок «Поставь время и возвращайся к своим делам». Внизу карточка: чипы 25/45/60, подпись «Без отвлечений», кнопка «Начать фокус». Нажатие запускает **существующий** таймер Carpo и блокировку.

### 6.2 Во время сессии
Пруд остаётся фоном (можно уйти в другие приложения — это нормально). Заголовок «Пруд подождёт. Ты — в фокусе», большой таймер, кнопка «Завершить». Никаких появлений и всплывашек. Пруд можно скрыть (экономия батареи).

### 6.3 Завершение
Шторка: «Сессия завершена · 45 мин теперь живут в пруду» → «Закрыть» → проигрываются появления новых открытий: по одному, с паузой ~2 с, объект плавно вырастает (scale 0.72→1, opacity 0→1, 1.4 с) + круги на воде + короткий тост «В пруду что-то новое · {reveal}». Если нового нет — один круг на воде и «Пруд стал чуть живее».

### 6.4 Прерывание
Кнопка «Завершить» → шторка «Почему завершаешь сессию?» с 6 причинами (2 колонки) и «Просто завершить». Выбор — одно касание. Затем «20 мин сохранены. Спасибо, что отметил(а) причину» → «Вернуться к делам». Если меньше 2 мин — «Сессия была совсем короткой — ничего страшного, пруд на месте».

### 6.5 Статистика (необязательно в MVP)
«Всего в фокусе: 12 ч 40 мин», «Дней у пруда: 9», список открытых элементов. Капли не показывать.

Тексты — `config/strings_ru.json`, причины — `config/interrupt_reasons.json`. Запрещённые слова: «серия», «пропустил», «потерял», «штраф», «XP», «очки».

## 7. Анимация

Параметры — `config/palette.json → motion`.
- **Карпы:** плавное блуждание. Цель — случайная точка в `swimZone`; поворот к цели не быстрее 40°/с; скорость ~3.5% высоты холста в секунду (±15% у каждой рыбы); иногда замедление до 30% на 2.5–6 с; отталкивание от соседей ближе 200 px холста. Голова в ассете смотрит вверх → угол поворота `atan2(vy, vx) + 90°`.
- **Хвост:** отдельная часть, вращение ±14° вокруг пивота (60, 208) в координатах viewBox 120×280, частота ~1.1 Гц × (0.35 + скорость/базовая).
- **Тень:** `koi_shadow` под рыбой, смещение (+6, +10) px холста.
- **Круги на воде:** раз в 7–16 с у головы случайного карпа (рыба касается поверхности).
- **Каустика:** слой `caustics` медленно дрейфует (≈ 6 px/с, туда-обратно).
- **Время суток:** фон воды из `water_day / water_dusk / water_night` с crossfade; поверх объектов тонировка multiply (цвет и прозрачность в `overlay`). Свечение фонаря и светлячки рисуются ПОВЕРХ тонировки.
- **Reduce motion:** скорость ×1/3, без каустики и частиц, появления — простым fade.
- **Производительность:** 30 fps достаточно; при скрытом экране / свёрнутом приложении анимацию останавливать полностью.

## 8. Слои отрисовки (снизу вверх)

`water → caustics → koiShadow → koi → surface (кувшинки, лотосы) → shore (камни, растения, коряга, фонарь) → overhang (сакура) → [тонировка времени суток] → glow (свечение фонаря) → ambient (светлячки, лепестки) → fx (круги, частицы)`

Карпы проплывают **под** кувшинками — так и задумано.

Координаты: `x, y` — центр в долях холста, `width` — ширина в долях ширины холста, `rotation` — градусы; у карпов `length` — длина в долях высоты холста. Нижние ~22% и верхние ~10% холста закрыты UI — важный декор туда не ставится.

## 9. Архитектура

```
FocusTimer (уже есть) ──► SessionRepository (журнал сессий)
                                   │
                                   ▼
                     PondProgressEngine (чистые функции)
                     scoreSessions → computeUnlocks → mergeUnlocked
                                   │
                                   ▼
               PondState (капли, дни, открытия, «уже показано»)
                                   │
                                   ▼
                         PondRenderer (только рисует)

AppBlocker (уже есть) — независим, только подписан на старт/стоп таймера
```

- **Источник правды — журнал сессий.** Состояние пруда всегда можно пересчитать из журнала (`computePond`). Это идемпотентно: повторный пересчёт не начисляет дважды.
- **Открытия хранятся отдельно** (`unlocked`) и объединяются с вычисленными — смена чисел в конфиге не может ничего отнять.
- **`seenUnlocks`** — что пользователь уже видел появившимся; разница `unlocked − seenUnlocks` проигрывается анимацией при следующем открытии экрана пруда (например, если сессия закончилась, когда приложение было свёрнуто).
- **Время сессии** считать по монотонным часам (не по системным: перевод часов не должен давать капли). `localDate` сессии — дата окончания в часовом поясе устройства.
- **Синхронизация телефон ↔ ПК** (если журнал синхронизируется): уникальный `id` сессии (UUID), слияние журналов по `id`, затем пересчёт. Никогда не суммировать «капли» между устройствами напрямую.
- **`scoringVersion`** в каждой сессии — на случай будущих изменений правил.

### Модель данных

```
FocusSession {
  id: UUID
  startedAt, endedAt: timestamp
  localDate: "YYYY-MM-DD"
  plannedMinutes: int
  focusedSeconds: int          // по монотонным часам
  endReason: completed | interrupted
  reasonCode: string?         // код из interrupt_reasons.json или null
  reasonNote: string?         // только для "other", ≤ 80 символов, хранится локально
  scoringVersion: int = 1
}

PondState {
  unlocked: Set<unlockId>      // никогда не уменьшается
  seenUnlocks: Set<unlockId>
  // drops / focusDays / stage — НЕ хранить как источник правды, вычислять из журнала
}
```

## 10. Тестирование

- `config/progress_test_vectors.json` — 19 сценариев (вход → ожидаемые капли, дни, стадия, открытия и разбор каждой сессии). Порт движка обязан проходить все. Эталон на JS: `node reference/checkVectors.mjs`.
- Ручная проверка: завершённая сессия, прерывание с причиной, без причины, < 2 мин, убийство приложения во время сессии, перевод системных часов, смена времени суток, reduce motion, повторный вход после недели простоя (ничего не изменилось и не «завяло»).

## 11. Что проверить на пользователях

Числа v1 предварительные. Через 2–4 недели посмотреть: долю прерываний с причиной и без, не выросло ли число коротких прерванных сессий (признак «фарма» бонуса), сколько дней до первого карпа. Менять только `progression.json`.
