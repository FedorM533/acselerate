# Протокол связи ПК ↔ телефон (версия 1)

Связь идёт по домашней сети Wi-Fi напрямую, без облака. Роль «сервера» играет «Фокус-пруд»
на ПК. Код: `focusfarm/phone/` (`hub.py` — сопряжение и токены, `lan.py` — сетевая часть).

## Безопасность

- Выключено по умолчанию (`network.lan_enabled: false`), кнопка «Подключить телефон» включает само. Пока выключено, программа слушает только `127.0.0.1`.
- Если включено, открывается **отдельный** порт (`network.port`, по умолчанию 8766) на частном
  адресе ПК (192.168.x.x / 10.x.x.x / 172.16–31.x.x). Интерфейс, настройки и управление сессией
  остаются на `127.0.0.1:8765` и по сети недоступны.
- Принимаем только клиентов из частных сетей. Снаружи, даже при проброшенном порте, ответ 403.
- Нужен токен. Токен выдаётся один раз при сопряжении, в базе хранится только его SHA-256.
  Телефон можно удалить в «Настройках» — токен перестанет действовать, связь разорвётся.
- Код (6 цифр, он же в QR) живёт 120 секунд, одноразовый. После 5 неверных попыток сгорает.
- Не более 5 телефонов. Размер сообщения до 64 КБ.
- Трафик не шифруется (обычный `ws://` внутри домашней сети). Не включайте в общественном Wi-Fi.

## Сопряжение

1. ПК: «Подключить телефон» (кнопка сама включает связь по Wi-Fi) → код из 6 цифр и QR с текстом `focusfarm://pair?h=<ip>&p=<порт>&s=<код>`.
   Поиск без QR: телефон шлёт UDP-пакет `FOCUSFARM_DISCOVER` на порт 48766 (широковещательно); ПК отвечает JSON `{"v":1,"name","host","port"}` только пока сопряжение открыто и только клиентам из частных сетей. Адрес в ответе должен совпадать с адресом отправителя.
2. Телефон: `POST http://<ip>:<порт>/pair` с телом `{"secret": "<секрет>", "name": "<имя телефона>"}`.
3. Ответ 200: `{"v": 1, "device_id": "...", "token": "..."}`. Токен телефон сохраняет у себя.
   Ответ 403: `{"detail": "<причина>"}`.

## Постоянная связь: `ws://<ip>:<порт>/phone`

Первым сообщением (в течение 5 секунд) телефон шлёт `{"type": "hello", "token": "..."}`.

| Направление | Сообщение | Когда |
|---|---|---|
| ПК → телефон | `{"type": "hello_ok", "v": 1, "name": "..."}` | токен принят |
| ПК → телефон | `{"type": "state", "v": 1, "active": bool, "hard": bool, "list_mode": "blacklist"\|"whitelist", "remaining_s": int, "session_id": int\|null, "break_left_s": int}` | сразу после подключения, при любом изменении и раз в 15 секунд |
| ПК → телефон | `{"type": "revoked"}` | телефон удалили на ПК; затем связь закрывается |
| ПК → телефон | `{"type": "error", "reason": "bad_token"}` | неверный токен |
| телефон → ПК | `{"type": "heartbeat"}` | раз в 15 секунд; тишина дольше 45 секунд — связь закрывается |
| телефон → ПК | `{"type": "report", "events": [{"kind": "blocked", "app": "com.example", "ts": 1760000000}]}` | события, в том числе накопленные без связи; до 100 за раз |
| ПК → телефон | `{"type": "report_ok", "accepted": n}` | ответ на report |

`kind`: `blocked` (закрыли приложение), `opened`, `service_off` (отключили службу блокировки),
`service_on`. Неизвестные виды отбрасываются. Названия приложений хранятся только в памяти ПК.

`break_left_s` > 0: идёт перерыв Pomodoro, `active` при этом `false` (блокировки нет), телефон показывает отдых.
Когда перерыв кончается, `active` снова `true`.

`active: true` означает «идёт учёба, телефон надо защищать» (сессия идёт, не пауза, и в настройках
защита включена для телефона). Свои списки приложений телефон хранит у себя и работает автономно,
даже если связи с ПК нет.

## Коды закрытия WebSocket

| Код | Причина |
|---|---|
| 4400 | первое сообщение не `hello` |
| 4401 | неверный токен |
| 4403 | клиент не из частной сети или устройство удалено |
| 4408 | не прислали `hello` за 5 секунд или нет heartbeat 45 секунд |
