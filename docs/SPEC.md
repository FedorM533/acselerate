## 1. Контекст

«Фокус-док» — подставка для телефона на столе + программа на ноутбуке.
- Пользователь кладёт телефон в подставку → начинается учебная сессия.
- Программа на ноутбуке смотрит, какое окно активно и был ли недавно ввод с клавиатуры/мыши, и определяет состояние: работает / возможно отвлёкся / отвлёкся / телефон вынут / пауза.
- Время честной работы превращается в игру «Фокус-ферма»: пока человек работает, на его огороде растут растения. Отвлёкся — рост останавливается, появляются сорняки. Урожай приносит монеты, за монеты открываются новые растения и грядки.
- Подставка (ESP32) реагирует светом и звуком. **Подставки пока нет**, поэтому датчик телефона и устройство должны иметь программную заглушку (mock), которой можно управлять из интерфейса.

Проект делается для студенческого акселератора: нужен надёжно работающий демо-режим и понятная статистика.

## 2. Принципы (обязательно соблюдать)

1. **Приватность.** Не использовать камеру и микрофон. Не делать скриншоты. Не записывать нажатия клавиш — только время с последнего ввода (через системный API, без глобальных хуков клавиатуры, если это возможно). Заголовки окон использовать только в памяти для классификации, **в базу не сохранять**; в базу пишем только категорию и имя процесса.
2. **Мягкость.** Растения никогда не умирают. Никаких «наказаний», из-за которых хочется бросить. Реакции усиливаются постепенно.
3. **Никакого ML.** Состояние определяется прозрачными правилами с настраиваемыми порогами.
4. **Всё локально.** Никакого облака, аккаунтов, внешних API. Сервер слушает только `127.0.0.1`.
5. **Простота.** Минимум зависимостей, без сборщиков фронтенда, без фреймворков там, где хватает стандартной библиотеки.
6. **Тестируемость.** Время — через абстракцию `Clock`, чтобы логику можно было тестировать без ожидания.

## 3. Что НЕ делаем в MVP

- Голосовой помощник, распознавание речи, камера, компьютерное зрение.
- Облачная синхронизация, аккаунты, мобильное приложение.
- Мультиплеер (парный режим — только идея на будущее, не реализовывать).

## 4. Стек

- **Python 3.11+**
- **FastAPI + uvicorn** — локальный сервер, REST + WebSocket.
- **SQLite** (стандартный `sqlite3`) — хранение.
- **PyYAML** — конфиги.
- **psutil** — имя процесса.
- **pywin32** (только Windows) — активное окно. Время простоя — через `ctypes` и `GetLastInputInfo`.
- **pyserial** — связь с ESP32.
- **pytest** — тесты.
- **Фронтенд:** один `index.html` + `app.js` + `style.css`, чистый JavaScript (ES-модули), без сборки. Графику фермы рисуем **своими** простыми SVG (не копировать ассеты чужих игр).
- **Прошивка:** Arduino (C++) для ESP32.

Основная ОС — **Windows**. macOS и Linux — «по возможности», с работающим запасным вариантом (см. 7.3).

## 6. Датчик телефона и устройство

### 6.1 Интерфейсы
- `PhoneSensor`: `is_docked() -> bool`, события `dock_changed`.
- `DeviceOutput`: `set_led(color)`, `play_sound(n)`, `is_connected()`.

### 6.2 Реализации
- `MockPhoneSensor` — состояние меняется через API `POST /api/dev/phone {"docked": true|false}` и через переключатель в интерфейсе (виден только при `mode: dev` или в демо-режиме).
- `SerialPhoneSensor` / `SerialDeviceOutput` — ESP32 по USB-serial. Порт выбирается в настройках (список портов через `serial.tools.list_ports`). При потере связи — не падать, показывать статус «подставка не подключена» и переключаться на mock.
- `MockDeviceOutput` — пишет команды в лог и отображает «виртуальную подставку» в интерфейсе (цветной круг + подпись звука).

### 6.3 Протокол (опиши в `firmware/PROTOCOL.md`)
Serial 115200 бод, строки, завершённые `\n`.

Устройство → ПК:
- `HELLO fw=0.1`
- `DOCK 1` / `DOCK 0` — телефон положили / убрали (с антидребезгом 300 мс на стороне устройства)
- `BTN PAUSE` — кнопка паузы
- `BTN NOTEBOOK` — долгое нажатие: режим «пишу в тетради»

ПК → устройство:
- `LED GREEN|YELLOW|RED|BLUE|OFF|BLINK_RED`
- `SOUND <n>` — номер mp3-файла на DFPlayer (1 — мягкий сигнал, 2 — сигнал «отвлёкся», 3 — «урожай собран», 4 — «сессия началась»)
- `PING` → ответ `PONG`

## 7. Монитор активности

### 7.1 Что получаем каждую секунду
- `idle_seconds` — секунды с последнего ввода.
- `process_name` — имя процесса активного окна (например, `chrome.exe`, `code.exe`).
- `window_title` — только в памяти, для классификации.

### 7.2 Классификатор (`config/rules.yaml`)
Категории: `work`, `neutral`, `distraction`.
Правила по имени процесса и по ключевым словам в заголовке окна (без учёта регистра). Пример стартового файла:

```yaml
default: neutral
rules:
  - category: work
    process: [code.exe, idea64.exe, pycharm64.exe, winword.exe, excel.exe, powerpnt.exe, acrord32.exe, notepad++.exe]
  - category: work
    title_contains: [moodle, stepik, "google docs", "документ", overleaf, leetcode]
  - category: distraction
    title_contains: [youtube, "вконтакте", vk.com, tiktok, twitch, "кинопоиск", "steam"]
  - category: distraction
    process: [steam.exe, telegram.exe, discord.exe]
```
Правила применяются сверху вниз, первое совпадение побеждает. Пользователь редактирует списки в интерфейсе (раздел «Настройки»).

### 7.3 Реализации по ОС
- **Windows:** `GetForegroundWindow`, `GetWindowText`, `GetWindowThreadProcessId` + psutil; простой — `GetLastInputInfo`.
- **macOS:** активное приложение через `NSWorkspace` (pyobjc, опционально); простой — `ioreg -c IOHIDSystem` (HIDIdleTime).
- **Fallback:** если ничего не доступно — `process_name = "unknown"`, категория `neutral`, простой = 0, и в интерфейсе предупреждение «монитор активности недоступен, работает только датчик телефона».

## 8. Машина состояний

Состояния: `IDLE` (нет сессии), `FOCUS`, `NOTEBOOK`, `MAYBE_DISTRACTED`, `DISTRACTED`, `PHONE_OUT`, `PAUSED`.

Входы на каждом тике (раз в секунду): `phone_docked`, `idle_seconds`, `category`, `notebook_mode`, `paused`, текущее время из `Clock`.

Пороги в `config/settings.yaml` (стартовые значения, будем подбирать по пилоту):

```yaml
thresholds:
  phone_grace_s: 30            # телефон можно достать на 30 с без последствий
  distraction_confirm_s: 30    # сколько секунд в категории distraction до DISTRACTED
  neutral_limit_s: 90          # сколько секунд в neutral до MAYBE_DISTRACTED
  idle_limit_s: 180            # простой без ввода до MAYBE_DISTRACTED (не в режиме тетради)
  maybe_to_distracted_s: 180   # сколько длится MAYBE до DISTRACTED
  recover_s: 5                 # сколько секунд «хороших» сигналов нужно, чтобы вернуться в FOCUS
  notebook_max_min: 45         # максимум режима тетради подряд, затем вопрос «ты ещё тут?»
session:
  auto_start_on_dock: true
  default_length_min: 25
  auto_end_after_phone_out_min: 10
```

Правила (приоритет сверху вниз):
1. `paused` → `PAUSED`.
2. Телефон не в подставке дольше `phone_grace_s` → `PHONE_OUT`. Если меньше — оставить предыдущее состояние.
3. Категория `distraction` дольше `distraction_confirm_s` → `DISTRACTED`; меньше — `MAYBE_DISTRACTED`.
4. `notebook_mode` включён (и категория не `distraction`) → `NOTEBOOK`.
5. Категория `work` и `idle_seconds < idle_limit_s` → `FOCUS`.
6. Категория `neutral` дольше `neutral_limit_s` или `idle_seconds >= idle_limit_s` → `MAYBE_DISTRACTED`; если `MAYBE_DISTRACTED` длится дольше `maybe_to_distracted_s` → `DISTRACTED`.
7. Иначе → `FOCUS`.

Гистерезис: из `MAYBE_DISTRACTED`, `DISTRACTED`, `PHONE_OUT` в `FOCUS` — только после `recover_s` секунд подряд «хороших» сигналов.

`state_machine.py` — **чистая функция/класс без ввода-вывода**, чтобы её было легко тестировать.

Жизненный цикл сессии (`manager.py`):
- Старт: телефон положили (если `auto_start_on_dock`) или кнопка «Начать» в интерфейсе. Пользователь (или автоматически) выбирает грядку и растение.
- Конец: кнопка «Завершить», или телефон вынут дольше `auto_end_after_phone_out_min`, или вышло запланированное время (тогда предложить перерыв 5 минут).
- Каждое изменение состояния — событие в шину и запись в таблицу `events`.

## 9. Игра «Фокус-ферма»

### 9.1 Растения (`game/crops.py`)
| id | Название | Нужно минут фокуса | Монеты за урожай | Цена открытия |
|---|---|---|---|---|
| radish | Редис | 10 | 5 | открыт сразу |
| carrot | Морковь | 25 | 15 | 30 |
| potato | Картофель | 40 | 25 | 80 |
| sunflower | Подсолнух | 60 | 45 | 150 |
| pumpkin | Тыква | 90 | 80 | 300 |

Числа вынести в конфиг, чтобы легко менять баланс.

### 9.2 Правила
- Огород стартует с сетки 3×3. Расширения: 4×4 за 200 монет, 5×5 за 500.
- В начале сессии выбирается пустая грядка и растение (по умолчанию — растение, которое ближе всего к запланированной длине сессии).
- Прогресс растёт **только в состояниях `FOCUS` и `NOTEBOOK`**: +1 секунда прогресса за секунду (умножить на `demo_speed`, см. 9.4).
- `MAYBE_DISTRACTED` — рост на паузе, растение «хочет пить» (визуально).
- `DISTRACTED` или `PHONE_OUT` — рост на паузе; за каждые 60 секунд непрерывного отвлечения на случайной грядке с растением появляется сорняк (максимум 3 сорняка на огороде).
- Сорняк убирается кликом, но **только после 5 минут фокуса** в текущей сессии («заработал право прополоть»). Пока сорняк на грядке соседнего растения — урожай этого растения −20% монет.
- Качество урожая (звёзды) по числу эпизодов `DISTRACTED`/`PHONE_OUT` во время роста растения: 0 → ★★★ (×1.5), 1–2 → ★★ (×1.0), 3+ → ★ (×0.7).
- Растение созрело → анимация, звук `SOUND 3`, кнопка «Собрать». Монеты = база × качество × штраф сорняков, округлить вниз.
- Если растение не дорастило за сессию — прогресс сохраняется до следующей сессии.
- **Серия дней:** день засчитывается, если было ≥ 25 минут фокуса. Серия 3+ дня → на огороде «дождь», +10% к скорости роста в этот день.
- **Магазин:** открытие растений, расширение огорода, декор без влияния на игру (пугало, забор, скамейка).
- Растения **никогда не погибают**.

### 9.3 Защита от «накрутки»
- Рост только при реальных сигналах работы (правила раздела 8).
- Режим тетради ограничен `notebook_max_min`; затем — вопрос «Ты ещё здесь?» с кнопкой; без ответа 2 минуты → `MAYBE_DISTRACTED`.

### 9.4 Демо-режим
- `mode: demo` в `settings.yaml` или переменная окружения `FOCUSFARM_DEMO_SPEED=30`.
- Ускоряет рост растений и таймеры порогов в N раз, чтобы на защите за 2–3 минуты показать полный цикл.
- В интерфейсе заметная плашка «ДЕМО ×30», чтобы жюри видело, что время ускорено.
- Панель разработчика (только в demo/dev): переключатель «телефон в подставке», принудительная категория окна.

## 10. Реакции (`reactions.py`)
| Состояние | Свет | Звук |
|---|---|---|
| IDLE | OFF | — |
| FOCUS / NOTEBOOK | GREEN | `SOUND 4` при старте сессии |
| MAYBE_DISTRACTED | YELLOW | — |
| DISTRACTED | RED | `SOUND 2`, повтор не чаще раза в 3 минуты |
| PHONE_OUT | BLINK_RED | `SOUND 1` один раз |
| PAUSED | BLUE | — |

Ограничение частоты звуков обязательно. Пользователь может отключить звук в настройках. Параллельно — мягкое уведомление в интерфейсе и (опционально) звук в браузере.

## 11. Хранение, API, интерфейс

### 11.1 SQLite (`data/focusfarm.db`)
Таблицы (минимум): `sessions` (id, start, end, planned_min, focus_s, notebook_s, distracted_s, phone_out_s, crop_id), `events` (id, session_id, ts, state, category, process_name), `plots` (x, y, crop_id, progress_s, weeds, quality_hits), `wallet` (coins), `unlocks`, `streak`, `settings_overrides`.
Заголовки окон в базу **не пишем**. Миграции — простой `schema_version`.

### 11.2 API
- `GET /api/state` — текущее состояние сессии, фермы, подставки.
- `POST /api/session/start` `{plot, crop, length_min}`; `POST /api/session/pause`; `POST /api/session/resume`; `POST /api/session/notebook` `{on}`; `POST /api/session/end`.
- `POST /api/farm/harvest` `{x, y}`; `POST /api/farm/weed` `{x, y}`; `POST /api/shop/buy` `{item}`.
- `GET /api/stats?range=day|week` — время по состояниям, число отвлечений, топ категорий/процессов отвлечения, хронология последней сессии.
- `GET/PUT /api/settings`, `GET/PUT /api/rules`, `GET /api/ports`.
- `POST /api/dev/phone`, `POST /api/dev/category` — только в dev/demo.
- `WS /ws` — раз в секунду: состояние, таймер, прогресс грядок, статус подставки, события (сорняк, урожай).

### 11.3 Интерфейс (всё на русском)
Вкладки:
1. **Ферма** (главная): сетка грядок с SVG-растениями по стадиям (семя, росток, молодое, взрослое, готово), сорняки, монеты, серия дней, погода.
2. **Сессия**: большой таймер, цветной индикатор состояния с понятной подписью («Работаешь», «Кажется, отвлёкся», «Телефон вынут»), кнопки «Пауза», «Пишу в тетради», «Завершить», статус подставки, виртуальная подставка при mock.
3. **Статистика**: сегодня / неделя; полоса-хронология сессии, раскрашенная по состояниям; время в фокусе; число и причины отвлечений.
4. **Магазин**.
5. **Настройки**: пороги, списки правил (добавить/удалить процесс или слово), звук вкл/выкл, выбор COM-порта, демо-режим.

Стиль: дружелюбный, «уютная ферма», крупные элементы, чтобы хорошо смотрелось на проекторе. Оригинальная графика.

## 12. Фазы работы

После каждой фазы: запусти тесты, кратко опиши, что сделано и как проверить руками, сделай git-коммит `Фаза N: ...` и **остановись, жди подтверждения**.

## 13. Правила работы агента

- Пиши код **просто**: понятные имена, короткие функции, комментарии и docstring на русском там, где неочевидно «почему».

- Не удаляй и не переписывай крупно уже принятый код без согласования.
- Любая ошибка оборудования или монитора активности не должна ронять программу: логируй и показывай понятное сообщение в интерфейсе.
